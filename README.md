## Подробный отчет о проделанной работе

### 1. Развертывание инфраструктуры (Terraform)
* **Динамическая конфигурация**: Проведена полная интеграция инфраструктуры через Terraform. Из манифестов полностью удален жесткий хардкод старых ID подсетей и групп безопасности. Конфигурация переведена на динамические ссылки (`.id`), что обеспечивает полную идемпотентность и готовность к моментальному переразвертыванию контура с нуля.
* **Автоматизация инвентаря**: Настроен специальный манифест для автоматической генерации файла `hosts.ini` для Ansible. Сразу после выполнения команды `terraform apply` актуальные приватные и публичные IP-адреса хостов сами записываются в конфигурацию автоматизации.

### 2. Организация веб-контура (Сайт)
* **Изоляция и безопасность**: Развернуты две идентичные виртуальные машины с веб-сервером Nginx в разных зонах доступности Yandex Cloud (`ru-central1-a` и `ru-central1-b`). Для обеспечения безопасности у серверов полностью отключен публичный NAT (`nat = false`), они изолированы в приватных подсетях и недоступны напрямую из интернета.
* **Балансировка трафика (L7)**: Для распределения входящего трафика между веб-серверами развернут Application Load Balancer (ALB). Созданы целевая группа (Target Group), группа бэкендов (Backend Group) с настроенным HTTP-хелсчеком на корень `/`, HTTP-роутер и виртуальный хост. Трафик распределяется равномерно, обеспечивая высокую отказоустойчивость сайта.

### 3. Настройка мониторинга (Prometheus + Grafana)
* **Сбор метрик**: Развернута отдельная виртуальная машина для системы мониторинга Prometheus. На оба веб-сервера установлены и запущены агенты `Node Exporter` (для системных метрик CPU, RAM, дисков) и `Nginx Prometheus Exporter` (для метрик веб-сервера). Аргументы запуска Nginx Exporter были исправлены для корректного сбора данных локально через `http://127.0.0`.
* **Визуализация (Grafana)**: Развернута ВМ с Grafana. В Ansible-плейбук добавлен шаг автоматического создания источника данных (Data Source provisioning). При запуске Grafana сразу имеет готовую и протестированную связь с Prometheus. Импортированы официальные дашборды для мониторинга утилизации ресурсов и http-ошибок.

### 4. Централизованный сбор логов (ELK-стек)
* **Контейнеризация сервисов**: Развернуты виртуальные машины под Elasticsearch (база логов) и Kibana (веб-интерфейс). Чтобы обойти жесткие геоблокировки официальных репозиториев Elastic для российских IP-адресов, сервисы переведены на Docker-контейнеры. Для скачивания образов Docker-демон был перенастроен на работу со стабильными зеркалами в РФ.
* **Доставка логов**: На веб-серверах развернуты Docker-контейнеры с агентом Filebeat. Конфигурационный файл `filebeat.yml` настраивается динамически через переменные Ansible (`hostvars`), автоматически получая актуальный приватный IP-адрес Elasticsearch. Агент успешно собирает логи `access.log` и `error.log` от Nginx и передает их в базу. Настройка защищена проверками синтаксиса и соединения (`filebeat test config/output`).

### 5. Сетевая связность и Bastion Host
* **Топология сети**: Развернута единая облачная сеть (VPC) с двумя подсетями. Публичные адреса выданы только балансировщику, Grafana и Kibana для доступа извне. Все остальные критические серверы находятся в закрытом контуре.
* **Организация доступа**: Для безопасного администрирования развернута ВМ, выполняющая роль Bastion-хоста (единственная точка с открытым наружу портом 22). Доступ ко всем приватным серверам по SSH настроен по цепочке строго через Бастион с использованием проброса SSH-ключей (`ProxyCommand`). Все группы безопасности (Security Groups) жестко ограничены и разрешают только необходимый для работы сервисов трафик.

### 6. Резервное копирование (Backup)
* **Отказоустойчивость данных**: В файле `backup.tf` настроено автоматическое создание снимков (snapshots) дисков. Список целевых объектов расширен: теперь резервному копированию подлежат диски **всех 7 виртуальных машин**, задействованных в проекте. Снимки делаются ежедневно, а время их жизни строго ограничено одной неделей (7 дней) для оптимизации расходов.
